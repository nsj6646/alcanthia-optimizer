# 알칸시아 플레이어 상태와 외출 보고서 조사

- 대상: [아이디와 외출 보고서로 게임 상태를 확보할 수 있는지 조사](https://github.com/nsj6646/alcanthia-optimizer/issues/3)
- 확인 시각: 2026-11-01 17:45 UTC (한국 2026-11-02 02:45). 시간에 따라 게임·약관이 바뀔 수 있다.
- 범위: 공개 공식 홈페이지·약관·게임 클라이언트 정적 파일과 비공식 팬 코드. 플레이어 ID나 계정으로 조회하지 않았고 로그인, 자격 증명 수집, 인증 우회, 게임 조작은 하지 않았다. 외출 보고서 **실제 스크린샷 표본은 확보하지 못했다**.

## 결론

**플레이어 ID만으로 최적화에 필요한 현재 상태를 합법적·안정적으로 가져올 수 있다는 근거는 확인하지 못했다.** 공식 게임 내부에는 ID를 사용하는 프로필 조회 코드가 있지만, 그 자체는 제3자용 공개 API의 제공이나 무인증 접근 허가가 아니다. 공식 UI에서는 2026-07-01부터 레벨·주요 달성 기록과 달리 텃밭 생산량·등록된 자동 연성 등 상세 정보는 친구에게만 표시한다고 명시한다. 서버의 실제 권한 검증과 제3자 API 제공 여부는 확인하지 못했다. [S1][S2]

공식 클라이언트와 과거 업데이트는 **외출 보고서가 표시하도록 구현된 항목**을 확인할 수 있게 해 준다. 그러나 실제 보고서 이미지, 한 화면에 들어가는 내용, 표시 조건별 결과와 OCR 정확도는 **미확인**이다. 아래 코드 분석을 특정 사용자의 스크린샷 관찰 결과로 취급하지 않는다. [S2]

### 공식 클라이언트가 보여 주는 것과 보여 주지 않는 것

[S2]의 `Lu`/`V_e`는 각각 ID 또는 닉네임을 사용해 게임 내부 친구 프로필을 조회하고 선택적으로 상세 상태를 요청한다. 요청 헤더를 만드는 `Mt`는 토큰이 있으면 Bearer 헤더를 추가한다. 이는 클라이언트 동작에 대한 관찰이지, 토큰 없는 요청이 서버에서 반드시 실패한다는 실험 결과나 외부 호출 허가가 아니다. 대상 플레이어에 대한 서버 요청은 하지 않았다. 공식 개발자 문서, 지원되는 제3자 API 계약, 필드·인증·요청 제한·갱신 주기를 확인하지 못했으며, **존재하지 않는다고 단정하지 않는다**.

공식 2026-03-27 패치는 당시 공개 프로필에서 자동 연성을 볼 수 있다고 했다. 그러나 같은 공식 클라이언트에 실린 **후속 2026-07-01 패치**는 기존 공개/친구 공개 설정을 없애고 위 상세 정보를 친구에게만 표시한다고 명시한다. 이전 패치만으로 현재 권한을 판단해서는 안 된다. [S2]

## 외출 보고서: 코드·업데이트로 확인한 범위

공식 클라이언트의 외출 보고서 클래스 `fHe`는 현재 오프라인 보고서를 `kee` 렌더러에 넘긴다. `kee.render`는 항목의 값이 있을 때만 여러 영역을 출력하는 조건문을 갖는다. 소스에서 확인한 **출력 예정 항목**은 다음과 같다. 이는 실측 스크린샷의 항목 목록이나 모든 상황에서 나타나는 필드가 아니다. [S2, `fHe`, `kee`, `Oee`, `Dee`]

- 외출 기간과 시작·종료 표시; 값이 있는 경우 골드, 모래시계 관련 항목, 마나 회복·소모 관련 항목.
- `텃밭`: 수확 아이템, 계승 씨앗 관련 항목. `연성`: 횟수, 사용·획득 아이템. `모험`: 승리 횟수, 사용 포션과 획득 아이템. `습격`: 방어 성공·피해 관련 횟수 및 관련 항목.
- 관련 내용이 없는 경우 `별다른 변화가 없었습니다`라는 문구를 출력하도록 구현돼 있다. 일부 영역이 안 보이는 것만으로 실제 값이 0이거나 전체 정보가 없다고 판단할 수 없다.

공식 업데이트에는 다음의 보다 구체적인 설명이 있다. 2026-07-01 연성 사용 재료는 반환분을 제외한 **실제 소진량**으로 표시하고 대성공을 강조한다. 2026-07-02 자동 사용 마나포션 정보가 더 상세해지고 재료 소비·획득 표기가 개선됐다. 2026-07-11 재료 순증감이 없는 연성도 횟수를 표시하도록 수정됐고, 2026-07-15 보고서를 모래시계 화면에서 확인하도록 변경됐다. 이들은 각각 당시의 변경 사항이지 표본 이미지의 실제 내용을 증명하지 않는다. [S2, 해당 날짜 패치]

**미확인:** 표본의 스크롤·페이지 구성, 실제 기기·해상도에서 가려지는 필드, 개별 솥 배정과 현재 재고·한도·현재 모험 상태의 표시 여부, 시간 경과 후 정확도, OCR로 읽을 수 있는 항목과 오류율. 보고서에 있는 사건별 변화는 현재 재고 스냅샷이나 현재 시간당 생산량과 구별해야 한다. 사용자에게 실제 화면을 요청한다면 자발적으로 제공한, 민감 정보가 가려진 본인 표본을 여러 화면·상태에서 확인한 뒤 판단한다. 표본 없이 OCR 필드 목록을 확정하지 않는다.

## 비공식 팬 구현과 주의점

팬 프로젝트 [S3]는 자신의 프록시를 통해 `userId` 또는 닉네임으로 텃밭을 조회하도록 구현하고, `grid`, `production`, `cauldronRecipeResults`, 모험 횟수 등을 표시한다. 별도 팬 프로젝트의 주장과 프론트엔드 코드일 뿐, 이 조사에서 프록시 서버의 인증 방식이나 실제 응답을 검증하지 않았다. 게임 운영자의 공식 제3자 API나 이용 허가의 증거로 삼을 수 없다. [S3, S4]

[S4]는 생산량을 서버 스냅샷으로 설명하며 약초·달빛버섯·밤그늘뿌리의 경우 이후 복제·부활 반복을 포함하지 않아 장기 생산량보다 낮다고 주장한다. 이 게임 규칙 해석은 **비공식·미검증**이다. 그래도 조회 시점 값과 장기 추정치를 구분하고, 계산 시각·게임 버전·누락 요소를 기록해야 한다는 경고로 유용하다.

[S3]는 운영진이 데이터 접근 방식을 막지 않는다는 전제를 적지만 구체적인 공식 허가 문서나 그 범위는 제시하지 않는다. 특히 공식 2026-07-01 패치의 친구 전용 상세 표시와 팬 README의 광범위한 텃밭 조회 설명 사이에는 **권한 범위가 불명확**하다. 실제 접근 권한이 충돌하는지 검증하지 않았으므로 우회 또는 이용 가능으로 결론 내리지 않는다. 팬 프록시에 실제 ID나 사용자 데이터를 전송하지 않았다. [S2][S3]

## 권한·약관·개인정보

- 공식 [이용약관 S5] 제7조는 사전 승낙 없는 서비스 취득 정보의 복제·제3자 제공, 비정상적 시스템 접근, 자동 프로그램 사용 등을 제한하고, 제10조는 계정 양도·대여를 금지한다. 제12조도 서비스 정보의 특정 복제·배포·상업적 이용을 제한한다. 단순 읽기 요청이라고 자동으로 허용된다고 가정하지 않는다.
- 공식 [2차 창작 가이드라인 S6]은 비영리 팬 사이트와 창작물의 스크린샷 사용을 허용 목록에 두지만, 원본 이미지 무수정 재배포와 AI 학습 데이터 활용을 금지한다. 이것이 자동 조회, 제3자 개인정보 처리, 임의의 OCR 모델 학습 또는 약관상 모든 데이터 복제의 포괄적 허가인지는 명시돼 있지 않다. 두 문서의 적용 관계와 이 도구의 구체적 사용 방식은 운영자에게 확인한다. 기성 OCR의 추론 자체가 학습에 해당한다고 단정하지 않는다.
- 공식 [개인정보처리방침 S7] 제2조는 이용자 식별자·닉네임·게임 이용 기록 등을 회사의 수집 항목으로 열거한다. 이 방침은 게임 운영자의 처리에 대한 것이지, 별도 도구의 개인정보 처리 권한을 부여하지 않는다. 본인 여부·동의·목적을 확인하고 ID, 닉네임, 화면 속 다른 사람의 정보는 민감하게 취급한다. 법적 판단은 상황에 따라 확인한다.
- 설계 권고: 필요한 정보만 본인이 입력하거나 본인이 가린 화면을 선택적으로 제공하고, 가능하면 기기 내 처리; 보관·전송이 필요하면 목적, 접근자, 보관 기간, 삭제 방법을 명시하고 최소화한다. 비밀번호·토큰·세션 쿠키는 받지 않는다. 보고서나 ID를 공개 이슈·로그·팬 프록시에 무심코 올리지 않는다. 사용자 동의가 운영자 허가나 약관 준수를 대체하지 않는다.

## 후속 확인

1. [공식 고객센터 S8](mailto:support@alcanthia.com)에 읽기 전용 제3자 도구의 사용 가능 API, 사용자·친구 권한, 허용 필드, 비로그인 접근, 요청 제한, 데이터 재사용 및 캡처/OCR 범위를 서면으로 문의한다. 허가 전에는 내부 API나 팬 프록시에 의존하지 않는다.
2. 사용자가 게임에서 직접 확인한 현재 생산량·재고·보관 한도·솥별 설정·모험 상태를 수동 입력할 수 있도록 [유저 상태 입력과 부족한 정보 처리 방식 확정](https://github.com/nsj6646/alcanthia-optimizer/issues/5)에서 검토한다. 현재 값과 보고서의 기간별 증감을 따로 기록하고 관측 시각 및 누락 상태를 명시한다.
3. 사용자의 동의하에 개인정보를 가린 실제 외출 보고서 표본과 필요 시 스크롤 화면을 확보해, 코드상 조건부 출력과 실제 표시·기간·누락을 대조한다. 샘플 확보 전 구현이나 정확도는 미정이다.
